## 一、仓位管理体系

### 1. 核心公式

**风险敞口公式（Kelly Criterion）：**
```
f* = (p × b - q) / b
p = 胜率（盈利交易 / 总交易）
q = 1 - p
b = 盈亏比（平均盈利 / 平均亏损）
f* = 理论最优仓位比例（Full Kelly）
```

**⚠️ 加密市场必须使用 Quarter Kelly（f* × 0.25）：**

Full Kelly 在传统市场中是理论最优，但加密市场波动远超传统市场，Full Kelly 等于自杀。

| Kelly 分数 | 实际仓位 = f* × 分数 | 适用场景 |
|-----------|---------------------|----------|
| Full Kelly (1.0) | f* | ❌ 加密市场禁用 |
| Half Kelly (0.5) | f* × 0.5 | ⚠️ 仍偏激进 |
| **Quarter Kelly (0.25)** | **f* × 0.25** | **✅ 加密市场推荐** |
| Eighth Kelly (0.125) | f* × 0.125 | 极端保守 |

**实例计算（Quarter Kelly）：**
```
胜率 p = 50%，盈亏比 b = 1.5
f* = (0.5 × 1.5 - 0.5) / 1.5 = 0.167（Full Kelly = 16.7%）
Quarter Kelly = 0.167 × 0.25 = 4.2%

账户 100,000 USDT → 单笔建议仓位 = 4,200 USDT
```

**实战简化版（2%法则）：**
```
单笔最大亏损 = 账户 × 2%
单笔仓位 = 单笔最大亏损 / 止损距离
```

**实例计算：**
```
账户：100,000 USDT
单笔最大亏损：100,000 × 2% = 2,000 USDT
止损距离：ATR × 2 = 1,000 USDT（BTC价格）
可建仓位：2,000 / 1,000 = 2手（≈0.033 BTC）

入场价：$65,000，止损价：$64,000
每手止损损失：$1,000
总仓位：2手 × $1,000 = $2,000（恰好2%）
```

### 2. 波动率调整仓位

**公式：**
```
调整后仓位 = 基准仓位 × (目标波动率 / 币种波动率)

目标波动率 = 账户 × 1% / 目标止损点数
币种波动率 = ATR(14) / 当前价格 × 100%
```

**实例：**
```
账户：100,000 USDT，目标止损1%
目标波动率 = 1% / 10% = 10%（账户容忍10%波动）

BTC波动率：ATR=$1,000，价格=$65,000 → 1.54%
调整后仓位 = 基准100% × (10% / 1.54%) = 649% → 实际最多100%

SOL波动率：ATR=$5，价格=$180 → 2.78%
调整后仓位 = 基准100% × (10% / 2.78%) = 360% → 实际最多100%

BNB波动率：ATR=$2，价格=$600 → 0.33%
调整后仓位 = 基准100% × (10% / 0.33%) = 3000% → 实际最多100%
但BNB实际应限制在30%以内（庄家风险）
```

### 4. 加仓策略

**金字塔加仓（趋势行情）：**
```
第1笔：10%仓位 — 入场信号确认
第2笔：+5%    — 浮盈>5%后，回调不破前低
第3笔：+3%    — 趋势加速，再次确认
第4笔：+2%    — 最后加仓，严格止损

风险：可能加在半山腰
优点：成本越来越低，浮盈保护
```

**倒金字塔（高确定性行情）：**
```
第1笔：30%仓位 — 极高确定性信号（如减半前）
第2笔：+20%   — 确认趋势后
第3笔：+10%   — 最后追入

风险：成本越来越高
适用：极强趋势 + 高确定性信号
```

**等比例加仓（推荐新手）：**
```
每笔等额加仓
优点：平均成本线性，不追高也不怕低
```

**动态加仓（专业级）：**
```
根据 ATR 变化动态调整：
ATR扩大 → 减仓（波动加剧）
ATR收缩 → 加仓（震荡蓄势）
```

### 5. 减仓与止盈

**固定比例止盈（标准版）：**
```
+10%  → 止盈1/3，剩余仓位移动止损到成本价
+20%  → 再止盈1/3，剩余1/3移动止损到+10%
+30%  → 全部止盈，或全部移动止损到+20%
```

**移动止盈（追踪止损）：**
```
入场合约价值 = 10,000 USDT
止损距离 = ATR × 2 = 500 USDT

+10%（合约11,000）→ 止损上移到 10,500
+20%（合约12,000）→ 止损上移到 11,500
+30%（合约13,000）→ 止损上移到 12,500

优点：让利润奔跑，亏损有限
```

**分批止盈公式：**
```
第1批（+10%）：卖出 1/3，止损移到成本
第2批（+20%）：卖出 1/3，止损移到+10%
第3批（+30%）：全部走，或留1/3看趋势
```

| 均值回归 | -5% | +15% | 3:1 |
| 突破策略 | -2% | +20% | 10:1 |
| 布林套利 | -1% | +3% | 3:1 |
| 网格交易 | -10%（总仓） | +1.5%/格 | - |

---

### 3. 止损执行原则

```
❌ 亏损时绝不移动止损（放大亏损）
✅ 盈利时可以上移止损（保护利润）
❌ 不在止损点附近手动平仓（等收盘确认）
✅ 收盘价跌破止损才执行
❌ 不因"还会涨回来"而不止损
✅ 止损是交易成本，如同手续费
```

## 六、组合回撤阶梯（Drawdown Regime）v3.2

> 根据账户当前回撤程度，自动切换操作模式，防止越亏越加的死循环

### 阶梯定义

| 阶梯 | 回撤范围 | 状态 | 操作规则 | 最大仓位 |
|------|---------|------|---------|----------|
| 🟢 GREEN | < 10% | 正常运行 | 按 Kelly 建议正常开仓 | 30% |
| 🟡 YELLOW | 10% ~ 20% | 警戒区 | 停止新开仓，仅允许对冲；现有仓位减至 2/3 | 20% |
| 🔴 RED | 20% ~ 30% | 危险区 | 强制减仓至 50% 以下，只保留核心仓位；禁止一切新开仓 | 15% |
| ⚫ BLACK | > 30% | 紧急区 | 市价平掉所有非核心仓位，仅保留 BTC/ETH | 10% |

### 回撤计算
```
当前回撤 = (峰值权益 - 当前权益) / 峰值权益 × 100%
```

### 回撤阶梯触发后恢复条件

| 退出阶梯 | 条件 |
|---------|------|
| BLACK → RED | 权益回升至峰值的 75% 以上 |
| RED → YELLOW | 权益回升至峰值的 85% 以上 |
| YELLOW → GREEN | 权益创新高（回到峰值以上） |

## 七、GARCH 波动率风险量化（v3.4 新增）

### 7.1 为什么需要 GARCH？

**传统波动率的问题**：
- 历史波动率（std）假设波动率是常数 → 错误
- ATR 只反映近期波动 → 无法预测未来
- 加密市场波动聚集效应明显（大涨后继续大涨/大跌）

**GARCH 优势**：
- 捕捉波动率聚集（Volatility Clustering）："今天波动大，明天大概率也大"
- 预测未来波动率（不只看历史）
- 计算风险价值（VaR）和条件风险价值（CVaR）

---

### 7.2 GARCH 模型原理

**GARCH(1,1) 公式**：
```
σ²_t = ω + α × ε²_{t-1} + β × σ²_{t-1}
```

| 参数 | 含义 | 典型值 |
|------|------|--------|
| ω (omega) | 长期波动率基准 | 0.01~0.1 |
| α (alpha) | 冲击衰减速度 | 0.05~0.2 |
| β (beta) | 波动率持续性 | 0.8~0.98 |

**关键性质**：
- α + β ≈ 1 → 波动率具有长记忆性（加密市场≈0.95~0.99）
- α 大 → 波动冲击衰减快（市场消化快）
- β 大 → 波动率持续久（恐慌延续）

### 7.5 VaR 与 CVaR 的区别

| 指标 | 含义 | 用途 |
|------|------|------|
| **VaR (风险价值)** | 在给定的置信度下，未来 N 天最多亏多少 | 监管报告、仓位限制 |
| **CVaR (条件风险价值)** | 当损失超过 VaR 时，平均亏多少 | 尾部风险控制、极端行情准备 |

**实例**：
```
VaR (95%) = -$523
→ 含义：95% 概率下，明天最多亏 $523

CVaR (95%) = -$734
→ 含义：如果明天亏超 $523（那 5% 的概率），
   平均会亏 $734（比 VaR 更警惕）
```

**加密市场必须用 CVaR**：
- VaR 忽略尾部风险（黑天鹅）
- CVaR 惩罚极端损失（更保守）

### 7.6 Python API 调用

```python
from risk_garch import GARCHRiskModel

# 初始化
model = GARCHRiskModel(symbol='BTCUSDT', interval='4h')

# 拟合 GARCH 模型
model.fit()

# 预测波动率
vol_forecast = model.forecast_volatility(days=7)
print(f"未来7天波动率：{vol_forecast[-1]:.2%}")

# 计算 VaR
var_95 = model.calculate_var(confidence=0.95, position=10000)
print(f"VaR (95%)：-${var_95:.0f}")

# 计算 CVaR
cvar_95 = model.calculate_cvar(confidence=0.95, position=10000)
print(f"CVaR (95%)：-${cvar_95:.0f}")

# 五级预警
risk_level = model.get_risk_level()
print(f"当前风险等级：{risk_level}")

# 多资产组合 VaR（考虑相关性）
portfolio_var = model.calculate_portfolio_var(
    symbols=['BTC', 'ETH', 'SOL'],
    weights=[0.5, 0.3, 0.2],
    confidence=0.99
)
print(f"组合 VaR (99%)：-${portfolio_var:.0f}")
```

### 7.7 GARCH vs 传统波动率

| 维度 | 历史波动率 (std) | ATR | GARCH |
|------|-------------------|-----|-------|
| 预测能力 | ❌ 只看历史 | ❌ 只看近期 | ✅ 预测未来 |
| 波动率聚集 | ❌ 忽略 | ❌ 忽略 | ✅ 捕捉 |
| 风险价值 (VaR) | ❌ 不准确 | ❌ 不适用 | ✅ 精确 |
| 极端行情 | ❌ 低估 | ❌ 滞后 | ✅ 预警 |
| 计算复杂度 | 低 | 低 | 中高 |

**实战建议**：
- 日常仓位管理：ATR 足够
- 极端行情预警：必须用 GARCH
- 组合风险管理：GARCH + DCC-GARCH（动态相关性）
