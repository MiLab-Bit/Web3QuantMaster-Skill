## 1. NUPL（未实现净利润/亏损）

### 公式
```
NUPL = (Market Cap - Realized Cap) / Market Cap
      = (市值 - 实现市值) / 市值
```

### 解读（比 MVRV 更精细）
| NUPL 区间 | 市场状态 | 操作建议 |
|-----------|-----------|-----------|
| > 0.75 | 狂热（顶部） | 清仓 |
| 0.5-0.75 | 乐观 | 减仓 |
| 0.25-0.5 | 希望/恐惧 | 持有 |
| 0-0.25 |  capitulation | 可买入 |
| < 0 | 悲观（底部） | 加仓 |

### 数据源
```python
# Glassnode API
url = "https://api.glassnode.com/v1/metrics/indicators/nupl"
params = {"a": "BTC", "api_key": "YOUR_KEY"}
```

## 2. RHODL 比率

### 公式
```
RHODL = 1周内的币天数销毁 / 1-2年内的币天数销毁
```

### 原理
- 短期持有者活跃 → RHODL 上升 → 接近顶部
- 长期持有者活跃 → RHODL 下降 → 接近底部

### 解读
| RHODL 分位数 | 信号 |
|--------------|------|
| > 0.95 | 顶部（卖出） |
| < 0.05 | 底部（买入） |

### 代码模板
```python
# fetch_rhodl.py
import requests

def fetch_rhodd_ratio(api_key, asset='BTC'):
    url = "https://api.glassnode.com/v1/metrics/indicators/rhodd_ratio"
    params = {
        "a": asset,
        "api_key": api_key,
        "i": "24h",
    }
    resp = requests.get(url, params=params, timeout=10)
    data = resp.json()
    
    # 计算分位数
    values = [d['v'] for d in data]
    current = values[-1]
    percentile = sum(1 for v in values if v <= current) / len(values)
    
    return {
        'current': current,
        'percentile': percentile,
        'signal': 'BUY' if percentile < 0.05 else 'SELL' if percentile > 0.95 else 'HOLD'
    }
```

## 3. 交易所净流量进阶分析

### 基础版问题
只看 `净流 = 流入 - 流出` 太粗糙。进阶分析：

### 3.1 按币种细分
```
BTC 净流入 → 可能看跌
ETH 净流入 → 可能看跌
稳定币净流入 → 可能看涨（场外资金入场）
```

### 3.2 按钱包聚类（Exchange vs Hot Wallet）
```
巨鲸 → 交易所：可能卖出
矿工 → 交易所：可能卖出
交易所 → 未知钱包：可能提现（看涨）
```

### 3.3 净流入的 7 日移动平均
```
7MA(净流入) > 0 持续 7 天 → 强卖出信号
7MA(净流入) < 0 持续 7 天 → 强买入信号
```

### 代码模板
```python
# exchange_flow_advanced.py
import numpy as np

def advanced_exchange_flow(api_key, asset='BTC', days=30):
    url = "https://api.glassnode.com/v1/metrics/exchange/netflow_total"
    params = {"a": asset, "api_key": api_key, "i": "24h", "f": "free"}
    resp = requests.get(url, params=params, timeout=10)
    data = resp.json()
    
    # 计算 7 日移动平均
    values = np.array([d['v'] for d in data[-days:]])
    ma7 = np.convolve(values, np.ones(7)/7, mode='valid')
    
    # 信号
    if ma7[-1] > 0 and all(ma7[-7:] > 0):
        signal = 'STRONG_SELL'
    elif ma7[-1] < 0 and all(ma7[-7:] < 0):
        signal = 'STRONG_BUY'
    else:
        signal = 'NEUTRAL'
    
    return {
        'current_flow': values[-1],
        'ma7': ma7[-1],
        'signal': signal,
    }
```

## 4. 巨鲸聚类分析（Cluster Analysis）

### 原理
不是追踪单个巨鲸地址，而是**聚类**：
```
同一实体的多个地址 → 聚类为一个"实体"
示例：Coinbase 所有热钱包 → 聚类为 "Coinbase 实体"
```

### 工具
- **Glassnode**：提供聚类后的实体数据（付费）
- **Whale Aler**（whale-alert.io）：实时监控巨鲸转账

### 进阶信号
| 信号 | 解读 |
|------|------|
| 巨鲸实体余额变化 > 5% | 机构级买卖 |
| 巨鲸实体之间的转账（实体 A → 实体 B） | 可能 OTC 交易 |
| 交易所聚类 → 未知聚类 | 提现（看涨） |
| 未知聚类 → 交易所聚类 | 存入（看跌） |

### 代码模板：追踪巨鲸实体余额
```python
# whale_entity_tracking.py
def track_whale_entities(api_key, min_balance_btc=1000):
    """
    追踪巨鲸实体余额变化
    需要 Glassnode 付费 API
    """
    url = "https://api.glassnode.com/v1/metrics/distribution/entity_balance_sum"
    params = {
        "a": "BTC",
        "api_key": api_key,
        "i": "24h",
        "min_balance": min_balance_btc,
    }
    resp = requests.get(url, params=params, timeout=10)
    data = resp.json()
    
    # 计算余额变化
    balances = [d['v'] for d in data]
    changes = np.diff(balances) / balances[:-1]
    
    # 信号：余额变化 > 5%
    signals = []
    for i, change in enumerate(changes):
        if abs(change) > 0.05:
            signals.append({
                'date': data[i+1]['t'],
                'change_pct': change * 100,
                'signal': 'BUY' if change < -0.05 else 'SELL'
            })
    
    return signals
```

## 5. 机构持仓追踪（ETF/上市公司）

### 数据源
| 机构类型 | 数据源 | 更新频率 |
|-----------|----------|------------|
| 美国 BTC ETF | SOsovalue / Glassnode | 每日 |
| 上市公司持仓（MicroStrategy 等） | Bitcoin Treasuries | 不定期 |
| 加拿大 ETH ETF | 公开披露 | 每月 |

### 代码模板：获取 ETF 持仓
```python
# etf_holdings.py
def fetch_etf_holdings():
    """
    获取美国 BTC ETF 持仓量
    数据源：Glassnode (免费额度可用)
    """
    api_key = 'YOUR_API_KEY'
    url = "https://api.glassnode.com/v1/metrics/distribution/etf_holdings"
    params = {"a": "BTC", "api_key": api_key, "i": "24h"}
    resp = requests.get(url, params=params, timeout=10)
    data = resp.json()
    
    # 计算持仓变化（7 日）
    holdings = [d['v'] for d in data]
    change_7d = (holdings[-1] - holdings[-8]) / holdings[-8] * 100
    
    signal = 'BUY' if change_7d > 2.0 else 'SELL' if change_7d < -2.0 else 'HOLD'
    
    return {
        'current_holdings': holdings[-1],
        'change_7d_pct': change_7d,
        'signal': signal,
    }

# 运行
if __name__ == '__main__':
    result = fetch_etf_holdings()
    print(f"ETF 持仓: {result['current_holdings']:,.0f} BTC")
    print(f"7 日变化: {result['change_7d_pct']:+.2f}%")
    print(f"信号: {result['signal']}")
```

## 6. 长期持有者 vs 短期持有者

### 定义
| 类型 | 持有时间 | 行为特征 |
|------|----------|------------|
| 长期持有者（LTH） | > 155 天 | 很少卖出，看涨 |
| 短期持有者（STH） | < 155 天 | 频繁交易，看跌 |

### 指标：LTH/STH 供应量占比
```
LTH 占比 > 70% → 筹码固化，上涨在即
STH 占比 > 70% → 散户接盘，下跌风险
```

### 数据源
Glassnode: `supply/active_wallets_1y_to_2y_sum` (LTH)
Glassnode: `supply/active_wallets_24h_sum` (STH)

### 代码模板
```python
# lth_sth_analysis.py
def lth_sth_ratio(api_key):
    url_lth = "https://api.glassnode.com/v1/metrics/supply/active_wallets_1y_to_2y_sum"
    url_sth = "https://api.glassnode.com/v1/metrics/supply/active_wallets_24h_sum"
    
    params = {"a": "BTC", "api_key": api_key, "i": "24h"}
    
    lth = requests.get(url_lth, params=params, timeout=10).json()
    sth = requests.get(url_sth, params=params, timeout=10).json()
    
    lth_supply = lth[-1]['v']
    sth_supply = sth[-1]['v']
    total = lth_supply + sth_supply
    
    lth_pct = lth_supply / total * 100
    sth_pct = sth_supply / total * 100
    
    signal = 'BUY' if lth_pct > 70 else 'SELL' if sth_pct > 70 else 'HOLD'
    
    return {
        'lth_pct': lth_pct,
        'sth_pct': sth_pct,
        'signal': signal,
    }
```

## 7. 矿工持仓指数（MPI）

### 公式
```
MPI = 矿工流出量 / 1 年移动平均(矿工流出量)
```

### 解读
| MPI | 含义 |
|-----|------|
| > 2.0 |  miner 大量卖出（看跌） |
| 1.5-2.0 | miner 适度卖出 |
| 0.5-1.5 | 正常 |
| < 0.5 | miner 囤币（看涨） |

### 数据源
Glassnode: `mining/outflows_total`

### 代码模板
```python
# miner_positioning_index.py
import numpy as np

def calculate_mpi(api_key, days=365):
    url = "https://api.glassnode.com/v1/metrics/mining/outflows_total"
    params = {"a": "BTC", "api_key": api_key, "i": "24h"}
    resp = requests.get(url, params=params, timeout=10)
    data = resp.json()
    
    outflows = np.array([d['v'] for d in data[-days:]])
    
    # 计算 1 年移动平均
    ma365 = np.mean(outflows)
    
    # 当前 MPI
    mpi = outflows[-1] / ma365
    
    signal = 'SELL' if mpi > 2.0 else 'BUY' if mpi < 0.5 else 'HOLD'
    
    return {
        'mpi': mpi,
        'signal': signal,
    }
```

## 8. 链上波动率指数（CVI）

### 原理
基于链上转账量的波动率，而不是价格波动率：
```
CVI = std(链上转账量, 30d) / mean(链上转账量, 30d)
```

### 解读
- `CVI > 2.0`：链上活动极度波动（可能恐慌或 FOMO）
- `CVI < 0.5`：链上活动平稳（可能底部）

### 代码模板
```python
# chain_volatility_index.py
def calculate_cvi(api_key, days=30):
    url = "https://api.glassnode.com/v1/metrics/transactions/transfers_volume_sum"
    params = {"a": "BTC", "api_key": api_key, "i": "24h"}
    resp = requests.get(url, params=params, timeout=10)
    data = resp.json()
    
    volumes = np.array([d['v'] for d in data[-days:]])
    
    cvi = np.std(volumes) / np.mean(volumes)
    
    signal = 'HIGH_VOL' if cvi > 2.0 else 'LOW_VOL' if cvi < 0.5 else 'NORMAL'
    
    return {
        'cvi': cvi,
        'signal': signal,
    }
```

## 9. 代码模板：Glassnode API 进阶查询

### 模板：批量获取多个指标
```python
# glassnode_batch.py
import requests
import pandas as pd

GLASSNODE_BASE = "https://api.glassnode.com/v1/metrics"

METRICS = [
    "indicators/mvrv_z_score",
    "indicators/sopr",
    "indicators/nupl",
    "exchange/netflow_total",
    "mining/outflows_total",
]

def batch_fetch_glassnode(api_key, asset='BTC', metrics=METRICS, days=90):
    """
    批量获取 Glassnode 指标，返回 DataFrame
    """
    df = pd.DataFrame()
    
    for metric in metrics:
        url = f"{GLASSNODE_BASE}/{metric}"
        params = {
            "a": asset,
            "api_key": api_key,
            "i": "24h",
            "f": "free" if 'free' in url else None,
        }
        
        try:
            resp = requests.get(url, params=params, timeout=10)
            data = resp.json()
            
            # 解析
            dates = [d['t'] for d in data]
            values = [d['v'] for d in data]
            
            df[metric.split('/')[-1]] = values
            
        except Exception as e:
            print(f"获取 {metric} 失败: {e}")
    
    return df

# 使用
if __name__ == '__main__':
    df = batch_fetch_glassnode('YOUR_API_KEY')
    print(df.tail())
    df.to_csv('glassnode_metrics.csv', index=False)
```

## 10. Dune Analytics 进阶 SQL 模板

### 模板 1：追踪巨鲸转账（BTC）
```sql
-- dune_whale_btc_transfers.sql
SELECT 
    date_trunc('hour', block_time) AS hour,
    SUM(transfer_value_btc) AS total_btc_transferred,
    COUNT(*) AS tx_count,
    SUM(CASE WHEN transfer_value_btc > 1000 THEN 1 ELSE 0 END) AS whale_tx_count
FROM 
    bitcoin.transfers
WHERE 
    block_time > NOW() - INTERVAL '7' DAY
    AND transfer_value_btc > 100  -- 忽略小额
GROUP BY 
    1
ORDER BY 
    1 DESC
```

### 模板 2：ETH 2.0 质押解锁日历
```sql
-- dune_eth2_unlock_calendar.sql
SELECT 
    DATE_ADD('day', 2048, withdrawal_time) AS unlock_date,  -- 2048 epochs ≈ 9 天
    SUM(amount_eth) AS eth_unlocked,
    COUNT(DISTINCT validator_index) AS validator_count
FROM 
    ethereum2.validator_withdrawals
WHERE 
    withdrawal_time > NOW()
GROUP BY 
    1
ORDER BY 
    1 ASC
```

### 模板 3：稳定币流动性分析
```sql
-- dune_stablecoin_liquidity.sql
SELECT 
    token_symbol,
    DATE_TRUNC('day', block_time) AS day,
    SUM(CASE WHEN to_label LIKE '%exchange%' THEN amount_usd ELSE 0 END) AS to_exchange,
    SUM(CASE WHEN from_label LIKE '%exchange%' THEN amount_usd ELSE 0 END) AS from_exchange,
    SUM(CASE WHEN to_label LIKE '%exchange%' THEN amount_usd ELSE 0 END) 
      - SUM(CASE WHEN from_label LIKE '%exchange%' THEN amount_usd ELSE 0 END) AS net_flow
FROM 
    stablecoin.transfers
WHERE 
    block_time > NOW() - INTERVAL '30' DAY
    AND token_symbol IN ('USDT', 'USDC', 'DAI')
GROUP BY 
    1, 2
ORDER BY 
    2 DESC
```

## 11. 总结：链上指标使用优先级

| 指标 | 可靠性 | 延迟 | 适用策略 |
|------|---------|------|----------|
| **交易所净流量** | ⭐⭐⭐⭐ | 1-24h | 中长线 |
| **MVRV Z-Score** | ⭐⭐⭐⭐⭐ | 实时 | 抄底逃顶 |
| **SOPR** | ⭐⭐⭐ | 实时 | 短线 |
| **NUPL** | ⭐⭐⭐⭐ | 实时 | 中长线 |
| **RHODL** | ⭐⭐⭐⭐ | 实时 | 抄底逃顶 |
| **巨鲸聚类** | ⭐⭐⭐ | 实时 | 中短线 |
| **机构持仓（ETF）** | ⭐⭐⭐⭐⭐ | 1 天 | 中长线 |
| **LTH/STH 占比** | ⭐⭐⭐⭐ | 1 天 | 中长线 |
| **MPI（矿工指数）** | ⭐⭐⭐ | 1 天 | 中长线 |

### 最佳实践
1. **组合使用**：不要只看一个指标（如 MVRV + NUPL + 交易所净流量 三重确认）
2. **注意延迟**：链上数据有 1-24h 延迟，不适合高频策略
3. **结合价格行动**：链上指标是「为什么」，K 线是「是什么」，两者结合
