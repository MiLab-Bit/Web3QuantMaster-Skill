# Contributing to Web3QuantMaster-Skill

Thanks for contributing to this quantitative research skill.

## Before submitting changes
- Search existing issues and pull requests and describe the intended use case.
- Keep pull requests focused; identify affected providers, strategies, data contracts and APIs.
- Never commit credentials, exchange API keys, private portfolio records or proprietary market data.

## Verification
- Report the exact commands and results for checks you ran; label any checks you could not run.
- Include deterministic fixtures or authorized public data, timestamps, timezone, symbol, exchange and source for market-data tests.
- Test missing/stale data, rate limits, partial failures and retry behavior where relevant.
- Distinguish simulated backtests from paper trading and real-money execution. Do not claim investment performance without verifiable evidence.
- Document breaking changes, dependencies and known limitations.

## Security and licensing
Do not disclose exploitable vulnerabilities in public issues; use a private maintainer reporting channel when available. Check the repository license and third-party dataset/provider terms before redistribution. Public visibility is not itself a reuse license.

## Review
Maintainers may request stronger evidence or narrower scope before merging.
